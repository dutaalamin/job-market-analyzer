Which skills are the job market actually asking for?

An end-to-end data platform that collects job postings, models them in a dbt-managed warehouse, and answers that question with SQL.

Pipeline and orchestration

collect.py → transform.py → load.py → dbt → analyze.py

Scheduled daily by an Apache Airflow DAG. The dbt layer models the warehouse and enforces 27 data-quality tests, all passing.

How it works

  1. Collect. Walks the Arbeitnow job board API page by page, 300 postings each, up to 3,000, and writes the raw JSON to disk before touching it. Re-runs read that snapshot, so the transform can be changed without hitting the network again.
  2. Transform. Strips double-escaped HTML, derives a role family and seniority from the title, and extracts skills from the title plus the full description. Duplicate postings are dropped on their source id.
  3. Load. Writes one table of postings and one of (posting, skill) pairs into DuckDB, with a SQLite mirror. Rebuilt from scratch every run, so the result is always a clean function of the input.
  4. Model. Five dbt models turn the raw tables into marts: skill_demand, role_families, seniority_mix, top_skills_by_family. 27 data-quality tests run alongside them: uniqueness of ids, accepted role and seniority values, and a share-of-market column that must stay between 0 and 100%.
  5. Analyse. The marts are queried into a single metrics.json that the page reads. No chart library: the donut and bars are computed in plain SVG.

A skill count is a count of postings that mention it, not a share of the market. The share above ("jobs yielding a skill") is the fraction of this corpus that produced one at all. The source is a general job board rather than a tech-only one, so that fraction is well under half.
